Scoring methodology

TEOI, constraints, and long-haul

The Terminal Expansion Opportunity Index is peer-relative, 0–100. A score is “how this airport looks versus the airports you asked about,” not a national grade. Missing features are dropped and remaining weights are renormalized. Gemini may quote the trace; it may not invent a different formula.

Why the score depends on the other airports

Each input (passengers, delay, gates, and so on) is stretched from 0 to 1 inside the comparison set S. The busiest airport in that set gets 1 on demand; the quietest gets 0. Ask “New England” and BOS is the high end, so its TEOI is high (about 70). Ask “only BOS” and there is nobody to beat, so every feature becomes 0.5 and the same airport can print ~37. That is not a new formula — it is a one-airport peer set. Follow-ups such as “why does BOS have this score?” reuse the last set; they must not re-rank BOS alone.

Formula

Peer-relative min-max inside comparison set S. Weights in navaid/scoring/weights.py sum to 1.0.

TEOI = 100 * (
  0.22 * demand_pressure +
  0.18 * congestion +
  0.18 * landside_saturation +
  0.15 * unmet_demand +
  0.12 * yield_mix +
  0.10 * growth_outlook +
  0.05 * capital_feasibility
) * constraint_multiplier
Default feature weights (sum 1.0)
FeatureWeightRole
Demand pressure0.22Enplanements / YoY pressure vs peers in S
Congestion0.18Delay / cancel / utilization vs peers
Landside saturation0.18Pax per gate (or related landside load) vs peers
Unmet demand0.15Load-factor gap + TAF gap + leakage
Yield mix0.12Long-haul / international mix as a yield proxy
Growth outlook0.10TAF / CAGR outlook vs peers
Capital feasibility0.05NPIAS/AIP feasibility; often the dropped weight

Constraint multipliers

Applied after the weighted sum. This is the investment thesis in arithmetic: more terminal does not create slots.

Constraint typeMultiplierMeaning
Landside1.00Terminal capex can unlock capacity
Mixed0.75Partly airside
Airside0.40Slots / runway / curfew / ATC bind
Demand-bound0.30Weak catchment; expansion is speculative

Drop-and-renormalize

If a feature is missing (for example no NPIAS for capital feasibility), that weight is removed and the remainder is rescaled to 1.0. Navaid never invents gate counts or TAF. The drop is listed on the ScoringTrace (weights_dropped, weights_used) and in the envelope.

Example: drop capital_feasibility (0.05). Remaining mass is 0.95. Demand pressure used weight becomes 0.22 / 0.95 ≈ 0.232. Contributions are 100 × weight_used × scaled_0_1. Then multiply by the constraint factor.

Unmet demand (clamped at 0)

  • Load-factor gap: served * max(0, LF − 0.85) / 0.85
  • Forecast gap: max(0, TAF_10y − implied_current_capacity) if TAF exists
  • Leakage: same-CBSA airports growing faster while origin LF is high

SFO’s spoken answer must match the engine. Load-factor gap is zero unless LF is above 85%. Same-metro leakage to OAK/SJC is counted only when that seat-pressure rule holds; otherwise it is qualitative. A TAF 10-year forecast gap can still produce unmet passengers. Slot/curfew remain the investment caveat: a forecast gap is not a missing concourse.

Long-haul: 4000 km

Great-circle kilometres on T-100 segments. Default threshold 4000 km (Eurocontrol). Report flight-segment share and passenger share, plus international share and optional pct_over_6h. Pin ANC→JFK at ~5420 km / 3370 mi. Cargo is out unless asked. Warehouse T-100 is a filtered commercial sample — totals will not match full-year FAA enplanements. T-100 is not true O&D: ANC→SEA→JFK is two segments.

Expansion rank vs EXPANSION_RANK

  • EXPANSION_RANK is the intent: run the ranker for a named peer set and return TEOI traces.
  • Expansion rank is the ordinal (1, 2, 3…) after TEOI and constraint multipliers. Rank 1 is the strongest terminal-expansion candidate in that set, not a national ranking and not FAA large/medium/small hub.
  • “Why is #2 above #3?” is EXPLAIN_TEOI on the last traces. It must not re-rank a single airport.

Ranker and congestion

Shared ranks (3, 3, 5); leftover ties by ICAO ascending. Deterministic.

Congestion compare has no fake single score. Payload: delay_pct, avg_arrival_delay_min, cancel_pct, ops_per_runway, live_faa_status, constraint_type, curfew, winner_on_each_axis.
